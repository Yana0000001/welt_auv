# Отчет по сборке ROS 2 pipeline для работы с камерами и записи данных

## 1. Как запустить проект
Запуск всей инфраструктуры (профиля зрения и автоматического логгера) осуществляется из директории расположения конфигурационного файла `docker/docker-compose.yml`:
```bash
cd docker/
docker compose --profile vision up -d
```

---

## 2. Какие камеры используются и параметры их интеграции
В проекте настроена работа двух независимых каналов обычных USB-камер через стандартный ROS 2 пакет `usb_cam`.

### Фронтальная камера (Физическая камера А)
* **Название / Тип:** Front Micro-Camera / Модуль курсового обзора.
* **Устройство (Стабильный путь):** `/dev/v4l/by-path/platform-3610000.usb-usb-0:2.4:1.0-video-index0`
* **Namespace:** `/camera_front`
* **Image topic:** `/stingray/topics/camera/front`
* **CameraInfo topic:** `/stingray/topics/camera/front/camera_info`
* **Optical frame:** `camera_front_optical_frame`

### Нижняя камера (Физическая камера Б)
* **Название / Тип:** Bottom Survey Camera / Обзорная камера дна.
* **Устройство / Serial Number:** `/dev/v4l/by-id/usb-Microsoft_Microsoft®_LifeCam_HD-3000-video-index0`
* **Namespace:** `/camera_bottom`
* **Image topic:** `/stingray/topics/camera/bottom`
* **CameraInfo topic:** `/stingray/topics/camera/bottom/camera_info`
* **Optical frame:** `camera_bottom_optical_frame`

## 3. Как обеспечивается стабильное соответствие камер
Для предотвращения динамической смены индексов устройств ядра Linux (`/dev/video0`, `/dev/video1`) при перезагрузках или скачках питания, в проекте реализовано монтирование по устойчивым путям `by-path` (привязка к аппаратному USB-порту хаба) и `by-id` (привязка к уникальному серийному номеру чипа камеры). 

В конфигурации Docker Compose полностью исключен небезопасный сквозной проброс всего каталога `- /dev:/dev`. Вместо этого применено изолированное точечное монтирование конкретных файлов путей `/dev/v4l/...`. Это гарантирует строгое сохранение связки «Физическое устройство ➔ Топик ROS 2» при любых перезапусках системы.

## 4. Какие топики записываются и обоснование набора (Computer Vision)
Для последующей оффлайн-обработки видео алгоритмами компьютерного зрения записывается строго минимальный ресурсосберегающий набор данных:
* `/stingray/topics/camera/front` и `/stingray/topics/camera/bottom` (`Image`) — сырые визуальные кадры.
* `/stingray/topics/camera/front/camera_info` и `/stingray/topics/camera/bottom/camera_info` (`CameraInfo`) — калибровочные матрицы линз для компенсации дисторсии.
* `/tf` и `/tf_static` — координатные трансформации.

**Обоснование необходимости топиков:** Запись одних лишь изображений дает плоскую статичную картинку. Без топиков `/tf` и `/tf_static` дерево пространственных связей между оптическими фреймами камер и центром масс робота (`base_link`) будет уничтожено. Включение трансформаций в баг-файл критически необходимо, чтобы оффлайн-алгоритмы могли рассчитать реальные 3D-координаты обнаруженных объектов в толще воды относительно робота.

## 5. Как задается QoS
Для топиков изображений высокого разрешения пакета `usb_cam` используется профиль `SensorData` (Best Effort доставка, небольшая глубина очереди), снижающий задержки. Регистратор `rosbag2` автоматически подстраивается под QoS издателя при записи. При оффлайн-воспроизведении логов используется флаг оверрайда для совместимости с любыми стандартными ROS 2 подписчиками (Reliable):
```bash
ros2 bag play /rosbags/<имя_сессии> --qos-profile-overrides-path qos_override.yaml
```

## 6. Как проверить запись и логика изоляции сессий
* **Изоляция сессий:** Выходная папка генерируется по уникальному шаблону времени `$(date +%Y-%m-%d_%H-%M-%S)` (Формат: `ГГГГ-ММ-ДД_ЧЧ-ММ-СС`). Это полностью исключает случайную перезапись старых логов.
* **Разбиение записи:** Настроен параметр `--max-bag-size 524288000` (500 МБ). Разбиение по размеру выбрано потому, что потоки видео генерируют плотный трафик; это защищает файлы от нечитаемости при сбоях.
* **Контроль места:** Хранение осуществляется на хост-накопителе через volume `:${HOME}/rosbags`. При переполнении SSD утилита `rosbag2` выбрасывает в консоль контейнера стандартную ошибку `IOError: No space left on device`, останавливая процесс, что сразу заметно оператору.
* **Корректное завершение:** В Compose добавлен флаг `init: true`, благодаря которому при остановке проекта (`docker compose stop`) контейнер корректно транслирует сигнал `SIGINT` в процесс `ros2 bag record`. Баг-файл успевает закрыть индексы и не повреждается.

**Команда проверки воспроизведения логов:**
```bash
ros2 bag info /rosbags/<название_папки_сессии>
ros2 bag play /rosbags/<название_папки_сессии>
```
